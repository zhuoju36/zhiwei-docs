# 什么是止危

**止危**（Zhiwei）是一个开源的结构健康监测（Structural Health Monitoring，SHM）平台，面向桥梁、建筑、风机、铁路等基础设施，提供从数据采集、存储、分析到可视化展示的一站式解决方案。

传统的结构健康监测系统往往面临以下问题：

- **封闭**：软硬件绑定，扩展困难，数据难以导出
- **昂贵**：商业软件授权费用高，中小项目难以承受
- **复杂**：部署与配置门槛高，工程人员难以上手
- **孤岛**：采集、分析、可视化工具割裂，难以形成闭环

止危的目标是用开源、模块化、可扩展的方式，让每个工程团队都能低成本地搭建自己的监测平台，让结构健康监测更广泛地服务于公共安全治理，提升城市人居品质。

## Zhiwei，不止止危

> **知微 → 止危 → 治未**

「止危」是平台的中文名，也是项目命名的锚点；但 Zhiwei 不止于「止危」。完整的工程理念是覆盖结构全生命周期三个阶段的递进——三者读音相连，构成完整的监测哲学。

### 知微

「几者，动之微，吉凶之先见者也。」——《易经·系辞下》

**感知层**：高频采样、微小信号捕捉、FFT / 模态分析，把现场的「毫厘之变」搬到工程师眼前。止危在通道层支持 100 Hz 起步的时序写入与频谱分析，让肉眼看不到的早期征兆变得可观测、可量化。

### 止危

「君子见几而作，不俟终日。」——《易经·系辞下》

**响应层**——也是项目得名之处。当通道读数越过阈值、频谱出现异常模态、趋势曲线显示发散，止危按规则触发告警并经 Webhook / Email 派发，让干预动作早于损伤成形。从知微到止危，时间尺度从毫秒延伸到秒与分钟。

### 治未

「上医治未病。」——《黄帝内经·素问》

**治理层**：时序库长期归档、跨季节 / 跨年的健康评估、寿命预测、维护决策支持。止危不仅在危险发生的瞬间做出反应，更致力于让结构在整个服役周期里「不生病、少生病、生小病」——这才是结构健康监测真正的长期价值。

### 三位一体

| 阶段 | 时间尺度 | 对应能力 |
| --- | --- | --- |
| 知微 | 毫秒 — 秒 | 高频采样、时序写入、FFT、看板 |
| 止危 | 秒 — 分钟 | 阈值告警、规则引擎、多渠道派发 |
| 治未 | 月 — 年 | 历史归档、健康评估、寿命预测 |

平台虽以「止危」为名，工程上追求的是「知微」之细、落到「止危」之准、走向「治未」之远。

## 核心能力

| 能力 | 说明 |
| --- | --- |
| 项目管理 | 项目-设备-传感器-通道四级组织，按项目隔离数据，普通用户需授权方可访问 |
| 数据接入 | 内置 MQTT、HTTP、Modbus TCP、DTU 透传（Modbus RTU over TCP）等适配器；新增协议 = 新增一个适配器文件 |
| 时序存储 | TimescaleDB hypertable，按通道粒度写入，单实例可达 10 万点/秒 |
| 实时计算 | 阈值告警、FFT 频谱、基础统计等插件，Celery 异步驱动 |
| 可视化 | 曲线、热力图、频谱、3D 模型联动（GLB 自动转换） |
| 告警通知 | 按通道配置告警规则，支持 Webhook、Email 多渠道并发派发 |
| 开放 API | RESTful API + Swagger UI + WebSocket 实时推送，方便二次开发 |

## 数据拓扑

```
用户 → 项目 → 设备 → 传感器（位置 + 仪器元数据）→ 通道（单位 / 采样率 / 告警规则）→ 读数
```

v0.9 起把测点与传感器合一——实际部署中一测点对应一个仪器，位置坐标与仪器元数据同行；单位、采样率、告警规则下放到通道，时序数据按通道存储与寻址。
